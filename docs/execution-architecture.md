
# Code Executor Architecture

## Project
Autonomous Multimodal Scientific Discovery Agent

## Assigned Role
Member 3 – Code Executor

## Objective
Develop a Python code execution component that receives
Python code generated by the AI agent, validates the
request, executes the code using Docker, captures the
execution results, and returns them to the calling agent.

## Execution Workflow

1. The AI agent generates Python code.
2. FastAPI receives the execution request.
3. Pydantic validates the submitted code.
4. The CodeExecutor prepares a Docker container.
5. Docker executes the Python program.
6. Standard output and errors are captured.
7. A structured response is returned to the caller.

## Technology Stack

- Python 3.12
- FastAPI
- Pydantic
- Docker
- Uvicorn
- Pytest

## Docker Configuration

- Python image: python:3.12-slim
- Network mode: none
- Memory limit: 128 MB
- CPU limit: 0.5
- Process limit: 64
- Read-only container filesystem
- Temporary filesystem for execution
- Execution timeout: 10 seconds by default

## API Interface

Endpoint: POST /execution/execute

Request fields:
- code
- language
- timeout_seconds

Response fields:
- status
- stdout
- stderr
- exit_code
- execution_time_ms
- truncated_output

## Initial Implementation

The initial implementation supports Python code
execution inside Docker and exposes the execution
functionality through FastAPI.

## Security Considerations

The execution environment uses Docker resource
restrictions and network isolation.

Additional security hardening is required before
production deployment.
